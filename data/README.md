# Dataset Contribution Guide

This folder contains the source of truth for the geospatial and organizational data used by the Robotaxi project. The YAML files here power the Supabase seed scripts in `supabase/seeds/` and the API routes that expose the data to the frontend.

## Repository Layout

- `data/cities.yaml` — cities with embedded country metadata; drives `supabase/seeds/cities.sql`.
- `data/robotaxis.yaml` — autonomous vehicle operators and headquarters.
- `data/ridehailings.yaml` — ridehailing companies and primary offices.
- `data/factories.yaml` — automotive manufacturing sites; drives `supabase/seeds/factories.sql`.
- `data/operations.yaml` — per ridehailing company, the countries and cities where they operate.
- `data/robotaxi-operations.yaml` — per robotaxi company, the cities where they operate; drives `supabase/seeds/robotaxi-operations.sql`.
- `data/universities.yaml` — universities mapped to city and country slugs.
- `scripts/generate_*_seed.sh` — Python-backed helpers that convert YAML into Supabase seed SQL.

## Data Standards

- **YAML style**: Use two-space indentation, keep lists alphabetised when practical, and prefer explicit keys even when values are empty (`source_id: ""` if the source is unknown).
- **Slugs**: Lowercase, dash-separated, ASCII only. City slugs must exist in `cities.yaml`. Country slugs must match the `slug` generated by the corresponding country entry in `cities.yaml`.
- **Coordinates**: Decimal degrees latitude and longitude with up to six decimal places. Use positive for N/E, negative for S/W.
- **Websites**: Omit scheme unless it is required (`example.com`, not `https://example.com`).
- **Optional fields**: Leave the key in place with a blank value rather than deleting it; the seed generators treat missing keys as `NULL`.

## Contribution Workflow

1. **Create a feature branch** in your fork or clone.
2. **Update the relevant YAML**:
   - Add new records at the end of the file or keep alphabetical ordering by slug.
   - Ensure referenced city and country slugs already exist; if not, add them to `cities.yaml` first.
3. **Install prerequisites** (first run only):
   ```bash
   pip install pyyaml
   ```
4. **Regenerate seeds** for any dataset you touched:
   ```bash
  ./scripts/generate_cities_seed.sh
  ./scripts/generate_ridehailings_seed.sh
  ./scripts/generate_robotaxis_seed.sh
  ./scripts/generate_operations_seed.sh
  ./scripts/generate_universities_seed.sh
  ./scripts/generate_factories_seed.sh
   ```
   Run only the scripts that correspond to the YAML files you modified. They validate required fields, uniqueness, and write updated SQL under `supabase/seeds/`.
5. **Check the repo** before opening a pull request:
   ```bash
   npm install
   npm run lint
   npm run check
   npm run format_check
   ```
6. **Review your diff** to confirm both YAML and generated SQL changes are present, then open a PR against `develop` (never `main`) describing the data source and verification steps.

## Dataset-Specific Guidelines

### `cities.yaml`
- Required keys: `slug`, `city`, `city_ascii`, `latitude`, `longitude`, `admin_name`, `capital`, `population`, `source_id`, `country`.
- `country` is an embedded map that must include `slug`, `name`, `iso2`, `iso3`; add supplementary metadata when available (`capital`, `region`, `population`, etc.).
- Capital value must be one of `primary`, `admin`, `minor`, or `none`.
- Each city slug must be unique. Reuse existing slugs when linking from other datasets.

### `ridehailings.yaml` and `robotaxis.yaml`
- Required keys: `slug`, `name`, `city`, `country`, `latitude`, `longitude`.
- Optional keys: `website`, `address`.
- `city` and `country` reference slugs defined in `cities.yaml`. Confirm they exist before committing.
- Keep company names in proper case; slugs stay lowercase.

### `operations.yaml`
- Each entry describes a single ridehailing network.
- Required key: `ridehailing-slug` matching an entry in `ridehailings.yaml`.
- `countries` and `cities` are lists of slugs. Remove duplicates; the generator de-duplicates but keeping the list clean eases review.
- If you add a new city operation, ensure the city exists in `cities.yaml`. For new countries, confirm the country slug is generated via `cities.yaml`.

### `universities.yaml`
- Required keys: `slug`, `name`, `website`, `country_iso`, `city`.
- `city_name` captures the human-readable label; `city` links to `cities.yaml` via slug.
- Prefer ISO Alpha-2 codes for `country_iso`.
- Populate coordinates where possible to support map visualisations.

### `factories.yaml`
- Required keys: `slug`, `city`, `manufacturer`, `latitude`, `longitude`.
- Optional keys: `focus`, `brand`, `address`, `rank`, `selection`.
- `focus` and `brand` accept either a YAML list or single string; the generator converts values into Postgres `text[]`.
- `city` references the slug defined in `cities.yaml`. The generator will fail if the slug is missing.
- Coordinates must use decimal degrees with up to six decimal places.
- Keep manufacturer names in proper case; slugs stay lowercase.

## Quality Checklist

- Added or updated slugs already exist in the upstream files they reference.
- No duplicate slugs were introduced.
- Seed scripts run without errors and regenerate the relevant SQL files.
- Lint (`npm run lint`) and type checks (`npm run check`) pass.
- Pull request description cites the external data source and date accessed.
